# Verify the primitives

## The promise

Every `create*` function the built barrel exports renders on the server inside Solid's `renderToString` while every name that `packages/primitives/tests/support/browser-resources.ts` lists throws when read. It reads none of them, gives the server value its case names, if it names one, and returns nothing, or a tuple or object that holds only functions, so destructuring it never freezes a value. Node's own loader imports the build.

In the browser, each primitive does what its test pins, in every engine that `enginesToVerify()` in `scripts/browser-engines.mjs` returns. Each request decides on the value staged by the requests before it in the same tick; a request that changes nothing writes nothing and calls nothing. Once its owner is disposed, a command writes nothing and calls nothing. No test raises a Solid development diagnostic, and once every root a test mounted is disposed, no listener, timer or observation that the harness recorded is left.

For any sequence of commands with flushes between some of them, every primitive whose source imports `./internal-value` agrees with a plain model after every step.

A primitive that returns a ref setter takes its ref, its memo and its effect from `createElementAttachment` in `internal-attachment.ts`, and imports no `createEffect` or `createMemo` of its own. The helper creates one signal, one memo and one effect on the server and the client alike, and its config reads no browser global, so a server render and its hydration create the same reactive nodes. No primitive reads `isServer` or applies `typeof` to `window` or `document`. Each element primitive the barrel exports attaches nothing before its ref receives an element, moves its attachment to each element the ref receives, removes it when its owner is disposed, records nothing in its ref after that, and keeps it for a config equal by value. The playground renders each one with a probe after it, and in its server render, hydrated in each engine, every probe is the element the server sent, claimed with the server's hydration id, and the listeners attach after hydration.

Where an event reaches its handlers in a fixed order, the one that handles it prevents its default and every later one ignores an event whose default is already prevented. Solid delegates `onKeyDown` to the root it renders into and runs the handlers from the innermost element out, and `createHotkeys` listens on `window` in the bubble phase, after them all. A press is different: each click-outside region decides on its own, by containment alone, and neither reads nor prevents its default. A press outside two regions calls both handlers, a press inside one and outside the other calls only the other's, and a layer portaled outside its parent's element counts as inside the parent only when the parent names it in `nodes`. Where a press starts is read on `window` in the capture phase, for each pointer on its own, so a widget that stops a `pointerdown` or a `pointerup` leaves nothing behind for a later press.

A focus trap neither reads nor prevents Tab. It watches where focus lands, and when focus lands outside its element it moves it to the element's first tab stop if the element that took it comes after, and to the last if it comes before, confirming each move and passing over an element that does not take focus. Only the trap turned on last does this: traps tell each other by events on their document, and a trap counts the newer ones. For any generated sequence of Tab and Shift+Tab presses among stops that are added, removed, disabled, hidden, made inert or given `tabindex="-1"`, focus never leaves the trap and lands where the engine's own Tab order, read through a mirror of the same stops, says. A focus return gives focus back only when focus is on the body, on nothing, or inside the surface when it closes. Hotkey parsing and matching agree with the matching rule for generated chords in Node. Every focus move goes through `moveFocus` in `internal-focus.ts`, and a public module that imports it, directly or through an internal module, awaits `expectNoAxeViolations` on the region it manages, which runs axe-core with every WCAG 2.2 A and AA tag that `axe.getRules()` names.

## The harm when it breaks

A primitive that reads `window` or schedules a timer during server rendering crashes the page on the server or keeps the process alive. A primitive that decides on the committed value instead of the staged one runs `onOpen` twice for a double press, so a dialog opens twice or an analytics event doubles, and a toggle pressed twice before a flush lands on the wrong option. A controlled input that drops a request leaves the consumer at the wrong value. A command that still runs after dispose calls back into a component that is gone, and so does a listener or timer left behind. A returned value that is not a function is frozen at its first value in every component that destructures it. An effect that the server does not create shifts every later hydration key, so the server's markup after it is left unclaimed and dead, and a detached copy takes the listeners. A trap that lets focus out leaves a keyboard user behind a modal surface, and one that computes its own Tab order sends focus to the wrong place or nowhere, past a shadow root, an editable element or a frame. Two traps that both guard fight over focus. A focus return that takes focus back from where the user put it swallows what they type next. A hotkey that runs before a widget's own handler closes the page's layer instead of the widget. A press that dismisses on `pointerdown` closes a popover when the user only meant to drag or select, against WCAG 2.5.2, and a press remembered from an earlier, hidden release closes it after a drag that started inside. A hotkey that fires during IME composition runs when a Japanese or Chinese user confirms a candidate with Enter. An axe violation in a focus surface is a barrier for assistive technology.

## Run it

```bash
vp test packages/primitives tests/primitive-conventions.test.ts apps/playground/tests/primitives-hydration.test.ts apps/playground/tests/dev-diagnostics.test.ts
```

It runs the server, build, hotkey, internal-module and convention tests in the node project, every browser test in each installed engine, and the playground's hydration check against its production server and its development server, also in each installed engine. With `CI` set, every engine must be installed, or the browser project fails as it starts.

## The tool and why

No verifier runs on Solid's reactive runtime, so this is not a proof. The model tests use fast-check's model-based commands inside the engine, against the primitives' source compiled by the Solid plugin with Solid's development build. fast-check generates command sequences, runs each against the primitive and a plain model, compares them after every step, and shrinks a failing sequence to the shortest one that still fails. The model is written from the promise above, not from the code: it holds a staged and a committed copy of the state and commits at each flush. The other browser tests drive real input where a primitive takes an event: presses through Vitest's pointer API and keys through its keyboard API, which Playwright sends as the engine's own input, and Solid's `onKeyDown` through the real compiler. A key pressed while an input method composes text, a press of several pointers at once, and a press inside a closed shadow root cannot be sent that way in every engine, so those tests dispatch the events. The server test renders the build with Solid's own server renderer. The hydration check is Playwright against the playground's real server render, because hydration needs markup that the server compiled and a client compiled to claim it. The Tab-order check uses the engine itself as the oracle: no specification of the order is written down to drift from it. axe-core checks the region a focus primitive manages against the WCAG rules it implements.

## What a pass covers

- Every `create*` function the built barrel exports, rendered on the server with every name in `browser-resources.ts` trapped.
- For each model test, the generated sequences its `fc.assert` runs per engine, a different set each run, at the size its `fc.commands` sets, with any number of commands between two flushes.
- The edge cases each browser test names.
- In every browser test, no Solid diagnostic and nothing left that the harness recorded, and the harness's own test, which shows it reports a leaked listener, timer, observation and diagnostic.
- Every rule of the primitive conventions, on the package and on its fixtures.
- For every element primitive the barrel exports, the five facts of the element contract, and its hydration in the playground, in the production build and the development build.
- For the focus trap, the generated sequences its property runs per engine, of Tab and Shift+Tab presses and changes to the starting stops, with the engine's order read again after every change. Its fixed tests add a link without `href`, a shadow root, an editable element, a frame, a click, a script, two nested traps, two stacked traps with the lower one inert or not, a removed focused element, and a widget that handles Tab with Solid's `onKeyDown`.
- For hotkey parsing and matching, generated chords in Node, with every casing, alias and order of the parts.

## What a pass does not cover

- Two page-wide hotkeys for one key: both listen on `window`, so the one attached first handles the key and the other ignores it.
- A key typed in a closed shadow root: `createHotkeys` sees its host, not the element, so the tags it ignores do not apply.
- Where a press ends inside a closed shadow root: only the press's start is read by a listener on the region.
- Focus that leaves the page for the browser's own controls, which a trap at the page's end lets it do, as a modal `<dialog>` does. When it comes back, the trap's rule picks the stop from where the element that took it lies.
- Links, scroll containers, positive `tabindex` and radio groups in the generated Tab sequences. Engines differ on links and scroll containers; the internal-module tests cover the order of the other two.
- Composition from a real input method. The composing event is dispatched.
- An axe rule outside the WCAG 2.2 A and AA tags, and markup other than the test's region. A primitive writes no attribute, so axe checks the markup a consumer builds around it.
- Firefox and WebKit on a machine where only Chromium is installed. CI runs every engine.
- A listener, timer or observer that a primitive registers outside the harness's scope: from a method of an object it returned, such as a `Map` that `createMap` returned, or from an effect that re-runs on a flush the harness did not make.
- A value whose type is a function passed where a primitive takes a value or an accessor: it is called.
- A primitive that keeps its state without `internal-value.ts` against a model. Its browser test pins fixed cases only.

## Reading a failure

- **`Property 'createX' is missing` from `vp check`.** A primitive was added without a server case, an element contract entry or a playground probe. Add the entry the message names.
- **`createX reads these browser resources on the server`.** The primitive reads a browser resource in its body or in a memo. Move the read into an effect's apply or a handler, which the server never runs.
- **`return accessors and handlers only`.** A primitive returns a plain value in its tuple or object. Return an accessor.
- **`a primitive raised a Solid development diagnostic`.** The message names the code, such as `REACTIVE_WRITE_IN_OWNED_SCOPE` for a write in the body or a memo. Fix the primitive; do not silence the diagnostic.
- **`a primitive left a listener, timer or observer behind`.** The message names each one, such as `a keydown listener on Window` or `a pointerdown listener in the capture phase on Window`. Return the cleanup from the attachment's attach function, or register it with `onCleanup` in the body.
- **`returns a RefSetter, so take its ref, its memo and its effect from createElementAttachment`.** An element primitive builds its own effects. Give its config and its attach function to `createElementAttachment`.
- **`after createX, the client claimed the server's element with the server's id: expected null`**, or **`Hydration key miss`** in the development diagnostics. The server and the client created different reactive nodes before the probe after that primitive. Look for an effect, memo or signal that one side skips.
- **`move focus with moveFocus from internal-focus.ts`.** Code calls `focus()` itself. Call `moveFocus`, which confirms the move.
- **`focus stays in the trap` or `focus lands where the engine's order says`, after `Counterexample`.** fast-check prints the starting stops and the steps, for example `[["button"],[{"type":"toggle","at":0,"change":"disabled"},{"type":"tab","backwards":false}]]`. Replay it by hand in that engine before you change the primitive.
- **An axe message such as `aria-roles: ARIA roles used must conform to valid values (div)`.** The region's markup breaks a WCAG rule. Fix the markup, not the tag list.
- **An `expect` fails after `Counterexample`.** This is a real break. fast-check prints the shortest sequence, for example `[false, toggle(), open()]`, and the message names the observation, such as `the callbacks that ran`. Report it in those terms. Do not loosen the model.
- **A fixed test fails.** Its name says which promise broke.
- **A fixture test of `tests/primitive-conventions.test.ts` fails.** A rule now flags code it allows, or misses code it forbids. Fix the rule; change a fixture only when the rule's promise changed.
- To replay one failure, add the printed `seed` and `path` to the options object passed to `fc.assert`, run again, and remove them afterwards.

## When the change is intended

- A new primitive: its server case, a `<file>.browser.test.ts` that imports the harness and pins every edge case it promises, a model test built on `tests/support/model.ts` when it keeps its state in `internal-value.ts`, an awaited `expectNoAxeViolations` when it imports `moveFocus`, and a doc comment on what the barrel exports.
- A new element primitive: return `createElementAttachment(config, attach, same)`, add its entry to the element contract and its probe to the playground, which the type check asks for, and delete from its own test what the contract checks.
- A new internal module that exports a function: a test named for it, in Node or in the browser.
- A new plain helper: a Node test named for it.
- A new command on a modelled primitive: add a command to its `commands`, with the model change it makes.
- A primitive that registers a listener, timer or observer: no change to the harness. A new kind of browser resource: add it to `browser-resources.ts`, which both the server trap and the harness read.
- Upgrading Solid, the Solid plugin, Vitest, Playwright, fast-check or axe-core: change the versions in the catalog in `pnpm-workspace.yaml`, then run the check.
- Mutation check after editing the covered code: in `packages/primitives/src/create-toggle.ts`, make `toggle()` advance from `index.get()` instead of `staged`, and run `vp test packages/primitives/tests/create-toggle.browser.test.ts`. It must fail with `each request decides on the value staged by the requests before it in the same tick, so two toggles of two options end where they started` and a counterexample. Restore the line afterwards.
- Hydration mutation: in `packages/primitives/src/internal-attachment.ts`, make `createElementAttachment` return its ref before `createAttachment` when `globalThis.document` is undefined, and run `vp test apps/playground/tests/primitives-hydration.test.ts apps/playground/tests/dev-diagnostics.test.ts`. It must fail with `the client claimed the server's element with the server's id` and a `Hydration key miss` warning. Restore the file afterwards.
- Focus mutation: in `packages/primitives/src/create-focus-trap.ts`, make the trap always move focus that leaves to the first stop, and run `vp test packages/primitives/tests/create-focus-trap.browser.test.tsx`. Its fixed tests and its generated test must fail, the generated one with `focus lands where the engine's order says` and a counterexample. Restore the file afterwards.
