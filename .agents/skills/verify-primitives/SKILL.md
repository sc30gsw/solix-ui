# Verify the primitives

## The promise

Every `create*` function the built barrel exports renders on the server inside Solid's `renderToString` while every name that `packages/primitives/tests/support/browser-resources.ts` lists throws when read. It reads none of them, gives the server value its case in `packages/primitives/fixtures/server-cases.ts` names, if it names one, keeps that value when the case calls its browser commands during the render, reads none of them when it calls its state commands, and returns nothing, or a tuple or object that holds only functions, so destructuring it never freezes a value. Node's own loader imports the build.

In the browser, each primitive does what its test pins, in every engine that `enginesToVerify()` in `scripts/browser-engines.mjs` returns. Each request decides on the value staged by the requests before it in the same tick; a request that changes nothing writes nothing and calls nothing. A command made by `createStateCommand` in `internal-command.ts` changes only reactive state and runs whenever its owner is live, before the owner's effects run too, and reads no browser resource when it is called during the server render; Solid itself refuses a write inside an owned scope, such as a component body. A command made by `createBrowserCommand` touches the browser, such as a scroll or a focus move, and never runs on the server. While the page hydrates it does nothing until an effect created after it has run: called in a component's body, or from the first run of an effect created before it, it does nothing, and called from the first run of an effect created after it, it acts. On a page the browser renders alone it runs whenever its owner is live. Solid gives no sign that hydration has ended before those first runs: `isHydrating()` is still true in them, and `onHydrationEnd` calls back after them, and on the server too. Once the owner is disposed neither does anything. No function typed `StateCommandBody` reaches a browser-only global, through any function it calls, in its module or another, so such a command is made with `createBrowserCommand`. A server case's state commands called before the owner's effects run change its value, and called after dispose, none of its commands changes a value or calls `scrollTo` or `focus`. No test raises a Solid development diagnostic, and once every root a test mounted is disposed, no listener, timer or observation that the harness recorded is left.

## The harm when it breaks

A primitive that reads `window` or schedules a timer during server rendering crashes the page on the server or keeps the process alive, and a command that runs there, such as a scroll, throws. A primitive that decides on the committed value instead of the staged one runs `onOpen` twice for a double press, so a dialog opens twice or an analytics event doubles, and a toggle pressed twice before a flush lands on the wrong option. A controlled input that drops a request leaves the consumer at the wrong value. A command that still runs after dispose calls back into a component that is gone, and so does a listener or timer left behind. A returned value that is not a function is frozen at its first value in every component that destructures it. An effect that the server does not create shifts every later hydration key, so the server's markup after it is left unclaimed and dead, and a detached copy takes the listeners. A value only the browser knows that is read during the server render crashes it, and one that reads the browser's value while the page hydrates renders markup the server did not send, which no Solid warning reports, so a layout jumps on load; a headroom that calls its callbacks for the loading value fires `onPin` and `onRelease` at a user who never scrolled. An error swallowed into a loading value hides a bug, and a throw that leaves a listener registered leaks it. An observer or subscription built again for an option equal by value drops its first report and the state built on it, so a headroom snaps back to fully shown. A listener in the bubble phase loses every event a widget stops, so the focused element or focus within reads wrong. A capture-phase listener that takes a descendant's event that does not bubble for its target's turns a hover false while the pointer is still on the element, and one that drops an event that bubbles from a descendant misses a selection made in an input. A focus move between two elements inside a region that is settled by `:focus-within` alone calls `onBlur` and `onFocus` in an engine where nothing is focused between the two events, and a commit handler on `onBlur` then fires on every Tab. An `instanceof` check fails for every node in a frame. An element value that still describes the old element after its ref moves draws the old size or the old hover for a frame. A trap that lets focus out leaves a keyboard user behind a modal surface, and one that computes its own Tab order sends focus to the wrong place or nowhere, past a shadow root, an editable element or a frame. Two traps that both guard fight over focus. A focus return that takes focus back from where the user put it swallows what they type next. A hotkey that runs before a widget's own handler closes the page's layer instead of the widget. A press that dismisses on `pointerdown` closes a popover when the user only meant to drag or select, against WCAG 2.5.2, and a press remembered from an earlier, hidden release closes it after a drag that started inside. A hotkey that fires during IME composition runs when a Japanese or Chinese user confirms a candidate with Enter. An axe violation in a focus surface is a barrier for assistive technology. A headroom threshold off by one hides a header at the very position its design fixes it, and a scroll direction that takes a layout shift for a scroll hides a header the user did not scroll away from.

## The tool and why

No verifier runs on Solid's reactive runtime, so this is not a proof. The model tests use fast-check's model-based commands inside the engine, against the primitives' source compiled by the Solid plugin with Solid's development build. fast-check generates command sequences, runs each against the primitive and a plain model, compares them after every step, and shrinks a failing sequence to the shortest one that still fails. The model is written from the promise above, not from the code: it holds a staged and a committed copy of the state and commits at each flush. The scroll models use fast-check's asynchronous model run: each step stands in a new scroll position, sends a `scroll` event, and waits with `applied`, then compares the value and the callbacks that ran. The other browser tests drive real input where a primitive takes an event: presses through Vitest's pointer API and keys through its keyboard API, which Playwright sends as the engine's own input, and Solid's `onKeyDown` through the real compiler. A key pressed while an input method composes text, a press of several pointers at once, and a press inside a closed shadow root cannot be sent that way in every engine, so those tests dispatch the events. The server test renders the build with Solid's own server renderer. The hydration check is Playwright against the playground's real server render, because hydration needs markup that the server compiled and a client compiled to claim it. The Tab-order check uses the engine itself as the oracle: no specification of the order is written down to drift from it. axe-core checks the region a focus primitive manages against the WCAG rules it implements.

## What a pass covers

- Every `create*` function the built barrel exports, rendered on the server with every name in `browser-resources.ts` trapped, with its case's commands called there.
- For every server case, its state commands called in the browser before the owner's effects run, and all its commands called after dispose.
- For every `BrowserValue` the barrel exports, its value in the production server's markup and while the page hydrates, which agree, and the browser's value after, in each engine, and no Solid diagnostic from it in the development build. For each one that takes no ref, its loading value with its browser API removed, and its subscription kept across an option recomputed to an equal value.
- For every observer, a real resize, intersection, mutation, focus move or pointer move, waited for through a control that saw the same event, the value it gives where its observer class is missing, and nothing left after dispose, including a frame scheduled by a report that the dispose interrupts.
- For each model test, the generated sequences its `assertProperty` runs per engine, a different set each run, at the size its `fc.commands` sets, with any number of commands between two flushes. For the scroll models, the generated setups and positions on the grid in `support/scroll.ts`, so a position often lands on a threshold.
- For `watchEvents`, a synthetic event that bubbles or not, aimed at the target or at a descendant, on an element, a shadow host, a document and a window, and real clicks, focus moves, pointer moves and scrolls, each with and without the event stopped below the target, against a bubble-phase listener on the same target.
- The edge cases each browser test names.
- In every browser test, no Solid diagnostic and nothing left that the harness recorded, and the harness's own test, which shows it reports a leaked listener, timer, observation and diagnostic.
- Every rule of the primitive conventions, on the package and on its fixtures.
- For every element primitive the barrel exports, the facts of the element contract, and its hydration in the playground, in the production build and the development build.
- For the focus trap, the generated sequences its property runs per engine, of Tab and Shift+Tab presses and changes to the starting stops, with the engine's order read again after every change. Its fixed tests add a link without `href`, a shadow root, an editable element, a frame, a click, a script, focus that enters the page with nothing focused before it, two nested traps, two stacked traps with the lower one inert or not, a removed focused element, a widget that handles Tab with Solid's `onKeyDown`, and four sequences and two built states that reach a focused container with the document selection inside it and no tab stop before the selection, each run once with a Tab and once with a Shift+Tab as the key that comes back, with the selection cleared, and, where the paragraph above says so, on an element with no trap and in a native modal `<dialog>`, a selection between two tab stops, and one state in which focus that leaves the document is allowed and five in which it must fail, where the test itself moves focus to the page that embeds the document in place of the key.
- For hotkey parsing and matching, generated chords in Node, with every casing, alias and order of the parts.

## What a pass does not cover

- Two page-wide hotkeys for one key: both listen on `window`, so the one attached first handles the key and the other ignores it.
- A key typed in a closed shadow root: `createHotkeys` sees its host, not the element, so the tags it ignores do not apply.
- Where a press ends inside a closed shadow root: only the press's start is read by a listener on the region.
- Focus that leaves the page for the browser's own controls from a trap at the page's end, as a modal `<dialog>` lets it: under the test runner the page is a frame, and what follows its end differs by engine. The test that focus coming back lands on the first stop blurs the focused element and focuses the page's first element with a script.
- Where focus goes when Shift+Tab takes it out of the trap's document. Under the test runner the document is a frame, and in the engines that leave it focus went to the runner's page that embeds it; a top-level page, where it would go to the browser's own controls, was not observed.
- Why the engine leaves the document from some states and not others with the same focus and selection. In Firefox, Shift+Tab from the focused container with the selection collapsed at its start left the document when the selection was put there after the container took focus, and did not when the container was blurred and focused again afterwards; no script can read that difference, so the generated check accepts both outcomes in that state.
- More than the generated sequences of one run. A hunt of 1,500 sequences in Firefox ran four times: it found the sequence that leaves one tab stop on its 76th in one run and the sequence that leaves two on its 1,387th in another, and found nothing in the other two; it took six minutes of every run and is gone, both finds are fixed cases, and no hunt has run against the exception as it is now written.
- The key that brings focus back after it left the document: the test driver sends it to the document's content, so it is not a user's way back, which goes through whatever holds focus first.
- Links, scroll containers, positive `tabindex` and radio groups in the generated Tab sequences. Engines differ on links and scroll containers; the internal-module tests cover the order of the other two.
- Composition from a real input method. The composing event is dispatched.
- For `createActiveElement`, a shadow root attached to an element that already has focus: a move from that host into the new root, or between two elements of it, sends the document neither `focusin` nor `focusout`, so the value stays on the host until focus has left it.
- For `createActiveElement`, a subscription that starts between the `blur` and the `focusin` of one Tab inside a shadow root, as when a `blur` handler creates the primitive or changes one of its options: it reads the body with no shadow root to watch, so the value stays on the body until focus leaves that root's host.
- For `createFocusWithin`, a focused element removed without a `focusout` inside a shadow root other than the one its element is in: one nested inside the element, or one that holds the host of the element's own. It watches removals in the element's document and in the element's own shadow root.
- An axe rule outside the WCAG 2.2 A and AA tags, and markup other than the test's region. A primitive writes no attribute, so axe checks the markup a consumer builds around it.
- Firefox and WebKit on a machine where only Chromium is installed. CI runs every engine.
- A listener, timer or observer that a primitive registers outside the harness's scope: from a method of an object it returned, such as a `Map` that `createMap` returned, or from an effect that re-runs on a flush the harness did not make.
- A value whose type is a function passed where a primitive takes a value or an accessor: it is called.
- A primitive that keeps its state without `internal-value.ts` or `createScrollFold` against a model. Its browser test pins fixed cases only.
- Real scrolls in the scroll models: they stand in the position and send the event. One fixed test scrolls the window for real.
- More than one scroll between two of Solid's flushes. A real scroll event gets a flush of its own, and a callback runs from an effect, once per change Solid applies.
- A real tab hidden by the browser, a real orientation change, a pointer leaving the page, a removed browser API, and a selection made by dragging: the tests replace the property or dispatch the event, and select text with a script or a double click.
- `device-pixel-content-box` in an engine that lacks it: the lookup that skips it is not exercised where every installed engine has it.
- A brand reached without a written assertion to `BrowserValue`, `never` or `any`: an assertion to a type parameter that a caller fills with `BrowserValue`, or a value already typed `any`, such as what `Reflect.get` returns, put where one is expected.
- A DOM member read by name in a way the rules do not resolve: a call that spreads both the object and the name from one array, such as `Reflect.get(...args)`, a name the type checker does not know as a string literal, a function called through an expression typed `any`, or through a type assertion that gives it another signature, such as `(lookUp as (...args: unknown[]) => unknown)(element, "focus")`, and a read through another function, such as `Object.getOwnPropertyDescriptor` or `Reflect.get.call`.
- A wait the rule does not name: `requestAnimationFrame`, a `timeout` whose number is computed, a timer reached through a helper in `tests/support`, and a count asserted another way, such as `.not.toBe(0)`.
- Whether every value only the browser knows is a `BrowserValue`: one read in an effect's apply into the primitive's own signal passes every rule. The rules check only that a primitive that reaches `branded` returns one, and that nothing else makes one.

## Reading a failure

- **`a public primitive reads layout here as it goes live`.** A primitive reads layout as it goes live and keeps what it read when the layout changes later. Read it inside a listener or an observer callback, follow the window's position through `internal-scroll.ts`, or, for a read at the moment of use that keeps nothing, add an entry with its reason to `layoutReadExemptions`.
- **`Property 'createX' is missing` from `vp check`.** A primitive was added without a server case, an element or browser-value contract entry, or a reveal in the hydration test. Add the entry the message names.
- **`createX reads these browser resources on the server`**, or a `ReferenceError` such as `window is not available on the server`. The primitive reads a browser resource in its body or in a memo. Move the read into a function typed `Subscription`, `Attach`, `BrowserCallback` or `BrowserCompute`, or into an effect's apply, which the server never runs.
- **`its server value after its browser commands ran`**, or a `ReferenceError` from a command during the server render. A command that touches the browser ran there. Make it with `createBrowserCommand`.
- **`make it with createBrowserCommand, not createStateCommand`.** A state command's body reaches a browser-only global. Make it a browser command.
- **`a state command called after the owner is created and before its effects run changes the value`.** A state command its server case names does not lead to the case's `after` before the first flush. Fix the command or the case's `after`.
- **`Type '() => T' is not assignable to type 'BrowserValue<T>'`** from `vp check`, or **`a value becomes a BrowserValue only through branded`.** A plain accessor stands for a browser value. Derive it with `mapBrowserValue`, or build it with `createBrowserValue`.
- **`return accessors and handlers only`.** A primitive returns a plain value in its tuple or object. Return an accessor.
- **`a primitive raised a Solid development diagnostic`.** The message names the code, such as `REACTIVE_WRITE_IN_OWNED_SCOPE` for a write in the body or a memo. Fix the primitive; do not silence the diagnostic.
- **`a primitive left a listener, timer or observer behind`.** The message names each one, such as `a keydown listener on Window` or `an observation by a ResizeObserver`. Hand the teardown to `keep` in a subscription, return it from an attach function, or register it with `onCleanup` in the body.
- **`returns a RefSetter, alone or in a tuple or object, so build it on createElementAttachmentWhen`.** An element primitive builds its own effects or signal. Give its attach function to `createElementAttachment` or `createElementValue`, or build it on another element primitive.
- **`reaches branded, the one place a value becomes a BrowserValue, so it returns its value as BrowserValue`.** The declared return type drops the `BrowserValue` alias, so the mapped types leave the primitive out. Declare `BrowserValue<T>`, alone or in a tuple or object.
- **`Property 'loadingValue' is missing`** from `vp check`. A browser value has no loading value, which the server needs: without it the server render throws `ASYNC_OUTSIDE_LOADING_BOUNDARY`. Pass the value its case in `fixtures/server-cases.ts` expects.
- **`createX: what it read while the page hydrated`.** The value read something other than the server's markup during hydration, so the client rendered markup the server did not send. Keep `ssrSource: "client"` in `internal-browser-value.ts`, and read the browser only inside the subscription.
- **`an option that recomputes to an equal value keeps the subscription`**, or **`an option that changes to a different value subscribes again`.** A config is compared by identity, or an option is read once where the subscription starts. Read it with `access` inside the config.
- **A rule names `catch`, `instanceof`, `listen`, `addEventListener`, an `on<event>` property, an observer, `ssrSource`, `globalThis` or a browser-only global.** The message says where it belongs. Find a missing API with `lookUp` or `browserMethod`, tell a node apart with `internal-node.ts`, listen through `watchEvents`, `handleEvent` or `listenAsAsked`, observe through `observe`.
- **`the server at http://127.0.0.1:<port>/ answered 500`**, with what the server printed. A primitive the playground renders throws on the server. The tests that need no page still run, so read what the browser-global rule and the server-render test say.
- **`while the page hydrates, a browser command called in a component's body or from the first run of an effect created before its primitive does nothing, and called from the first run of an effect created after it acts`.** Each entry names its caller. An empty list means the command waits past the first run of an effect created after it; an entry for the component's body, or for the effect created before the primitive, means it ran earlier than its doc comment says.
- **`poll with engineWait, wait with reported, or assert that nothing happened once witnessed has seen a control`.** A browser test waits by itself. Poll with `engineWait`, wait with `reported`, or assert that nothing happened once `witnessed` saw a control.
- **`after createX, the client claimed the server's element with the server's id: expected null`**, or **`Hydration key miss`** in the development diagnostics. The server and the client created different reactive nodes before the probe after that primitive. Look for an effect, memo or signal that one side skips.
- **`watchEvents on an element sees an event that does not bubble, aimed at a descendant exactly when a bubble-phase listener there would`**, or another case of that test. `watchEvents` delivers an event a bubble-phase listener on the target would not get, or drops one it would. Fix its one condition in `internal-listener.ts`; do not filter at a call site.
- **`write a doc comment directly above createX`.** The function the barrel exports has no doc comment, or a helper stands between the comment and it. Put the comment directly above the function, above its first overload.
- **`move focus with moveFocus from internal-focus.ts`.** Code calls `focus()` itself. Call `moveFocus`, which confirms the move.
- **`focus stays in the trap` or `focus lands where the engine's order says`, after `Counterexample`.** fast-check prints the starting stops and the steps, for example `[["button"],[{"type":"toggle","at":0,"change":"disabled"},{"type":"tab","backwards":false}]]`. Replay it by hand in that engine before you change the primitive.
- **An axe message such as `aria-roles: ARIA roles used must conform to valid values (div)`.** The region's markup breaks a WCAG rule. Fix the markup, not the tag list.
- **An `expect` fails after `Counterexample`.** This is a real break. fast-check prints the shortest sequence, for example `[false, toggle(), open()]`, or for a scroll model the generated setup, with each field named, and the scrolls, and the message names the observation, such as `the callbacks after a scroll to 25`. Report it in those terms. Do not loosen the model.
- **A fixed test fails.** Its name says which promise broke.
- **A fixture test of `tests/rules/primitive-conventions.test.ts` fails.** A rule now flags code it allows, or misses code it forbids. Fix the rule; change a fixture only when the rule's promise changed.
- To replay one failure, add the printed `seed` and `path` to the parameters passed to `assertProperty`, run again, and remove them afterwards.

## When the change is intended

- A new primitive: its case in `fixtures/server-cases.ts`, with its ref and its commands if it has them, a `<file>.browser.test.ts` that imports the harness and pins every edge case it promises, a model test built on `tests/support/model.ts` when it keeps its state in `internal-value.ts`, an awaited `expectNoAxeViolations` when it reaches `moveFocus`, and a doc comment directly above the function the barrel exports, which the export rule asks for.
- A new element primitive: build it on `createElementAttachment`, `createElementAttachmentWhen` or `createElementValue`, or on another element primitive, add its entry to the element contract and its reveal to the hydration test when it returns a value, which the type check asks for, and delete from its own test what the contract checks.
- A new value only the browser knows: build it on `createBrowserValue` with a loading value, derive any value from it with `mapBrowserValue`, read its options in its config, look its browser API up with `lookUp` or `browserMethod`, return it as `BrowserValue`, and give its server case that loading value. Add its browser-value contract entry, its missing API and its reveal, which the type check asks for.
- A new primitive that folds scroll positions: build it on `createScrollFold` with pure reducers, and a model test with `fc.asyncModelRun` over generated scroll positions, which the model-test rule asks for.
- A new internal module that exports a function: a test named for it, in Node or in the browser.
- A new plain helper: a Node test named for it.
- A new command: make it with `createStateCommand` when it changes only reactive state, and with `createBrowserCommand` when it touches the browser, which the command rule asks for when its body reaches a browser-only global. On a modelled primitive, add a command to its `commands`, with the model change it makes. Name it in its server case as a state command, with the value it leads to, or as a browser command.
- A primitive that registers a listener, timer or observer: no change to the harness. A new kind of browser resource: add it to `browser-resources.ts`, which both the server trap and the harness read; a new observer class goes in `observerNames`.
- Upgrading Solid, the Solid plugin, Vitest, Playwright, fast-check or axe-core: change the versions in the catalog in `pnpm-workspace.yaml`, then run the check.
