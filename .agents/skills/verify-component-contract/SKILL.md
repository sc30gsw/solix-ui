# Verify the component root contract

## The promise

For every exported component, the root element carries the stable class `solix-<Component>-root` and no other component's root class, unless `component` names another component, every class the consumer switched on, none the consumer switched off, and every attribute the consumer passed. Without `unstyled`, the root starts with exactly the classes of the component's compiled root styles, and then its stable root class, so the root of `Box`, whose root styles are empty, starts with its stable root class.

Every component also takes `classes`, `styles` and `unstyled`, and its parts are the keys of its built `styles` object, each rendered as one element that starts with exactly the classes that key compiles to and then the stable class `solix-<Component>-<part>`. A class that `classes` names for a part is on exactly that part's element and on no other, after the library's classes and the part's stable class, and on the root the consumer's `class` comes after `classes.root`. The declarations that `styles` names for a part are exactly that part's `style`, less any whose value is `undefined` or `null`, and on the root the consumer's `style` comes after `styles.root`, so it wins, and a declaration in it whose value is `undefined` or `null` replaces nothing. With `unstyled`, no element carries a class of the component's compiled styles, every part keeps its stable class on the same element, and every consumer class stays where it was. Every component takes every style prop, `hiddenFrom` and `visibleFrom` on its root, with `unstyled` or without, except a prop its type declares `never`: `Modal` takes no `display`, `hiddenFrom` or `visibleFrom`, and none of them reaches its root as a class or a property.

Each value a style prop is given, at its base or at a breakpoint, puts one `sx-` class on the root and writes into `style` the one `--sx-` custom property that class reads, and nothing else. `null` and a value that holds `;`, `{` or `}` put neither. An alias puts the class and property of the prop it aliases. `hiddenFrom` and `visibleFrom` each put one class and no property. The consumer's own `style` keeps every declaration it sets, including a `--sx-` one. No prop that `createParts` handles, but `class` and `style`, and no prop a fixture gives, but `children`, reaches any element as an attribute. Every component reads each prop of its type that takes an element, such as `children` or a section of `Tabs.Tab`, once in a server render of its fixture, so an element a consumer passes is created once. Given `0` for such a prop it renders the `0`, and given `null`, `undefined`, `false`, `true`, an empty string or an empty list it renders what it renders without the prop. A component that another export carries as a static member, as `Tabs` carries `Tabs.List`, is exported under the carrier's name followed by the member's, and rendered outside its carrier it throws an error that names the carrier. The root of `Box` and `Button` is the element their `component` prop names. Given a component as `component`, they resolve every style prop themselves, display ones included: a function component that spreads its props on a `<section>` gets the `sx-` classes and custom properties, and no `display` or `hiddenFrom` attribute. They also pass that component `classes`, `styles` and `unstyled`: `Box` wrapping `Button` with `unstyled` leaves the `<button>` with none of `Button`'s library classes. For a fixed set of cases written from the requirement, the class and the value are exactly the ones the requirement names: `mt={16}` is `1rem`, `bg="error"` is the error token's `var()`, `c="inherit"` is `inherit`.

## The harm when it breaks

A consumer's `class` silently does nothing, or it replaces the library's classes and the component loses its style. An attribute such as `id`, `aria-label` or `disabled` never reaches the element, so a label points at nothing or a control stays enabled. A class or declaration meant for one part lands on another, `unstyled` leaves the library's look in place or takes the stable classes a consumer's stylesheet targets, a style prop on a component other than `Box` does nothing, a closed `Modal` that is given `display` shows on the page, a component that `Box` or `Button` wraps gets `hiddenFrom` as an attribute and never hides, or `unstyled` on `Box` leaves the look of the `Button` it wraps. A component passed as an icon is instantiated twice, and in development the second copy misses its hydration key.

## The tool and why

No verifier runs on Solid components, so this is not a proof. The test uses fast-check to generate consumer props and renders each built component to a string with Solid's own server renderer, then reads the root element, and each element that carries a stable part class, out of the markup. Nothing is modelled by hand, and the expected classes come from the generated input, not from a run of the component.

## What a pass covers

- `generatedRuns` generated cases per component per run, as `component-contract.test.tsx` sets it, a different set each run.
- Distinct class names per case, as many as `arbitraries.ts` draws. Each is switched on or off, and written as part of a string, as an array item, or as an object key, all inside one nested `class` value.
- Any subset of `id`, `title`, `aria-label` and `data-state`, plus the component's boolean attribute set to true or false.
- Every component exported from `index.ts`. A component that is exported and missing from `fixtures` fails the type checker and the first test.
- That every key of each component's built `styles` object is rendered, under its fixture's props, on one element that starts with exactly the classes that key compiles to and then its stable class, with the root first.
- For each component, a set of `generatedRuns` cases for each of `classes`, `styles` and `unstyled`. In the first, distinct class names, as many as `arbitraries.ts` draws, each switched on or off and written as a string, an array item or an object key, are spread over its parts in `classes` and over the `class` prop. In the second, declarations of the properties `arbitraries.ts` names for each part in `styles`, each with a value, `undefined` or `null`, and a consumer `style` that is absent, an object of the same declarations whose values may be `undefined` or `null`, or a string of present ones, with `unstyled` on or off. The third is the first with `unstyled` on.
- For every component, another `generatedRuns` cases, each with style props drawn from the table, as many as `arbitraries.ts` allows, aliases included. A value is a scale key of any scale, a CSS-wide keyword, a raw length, a number, `null`, or a string that holds `;`, `{` or `}` among other text, and is written plainly or as a responsive object with any of `base`, `xs`, `sm`, `md`, `lg` and `xl`. Each case also draws `hiddenFrom` and `visibleFrom` (a breakpoint or `null`), a consumer class, a consumer `style` that may set a `--sx-` property itself, a `styles.root` that may set the `--sx-` property of a drawn prop to a value, `undefined` or `null`, and `unstyled` on or off, and for `Box` and `Button` a `component` of `div`, `section`, `article`, `span` or `a`. It renders each case twice and requires the same markup. These cases check the wiring only: how many classes and custom properties appear and that each class has its property, and that `Modal` puts nothing on its root for `display`, `hiddenFrom` or `visibleFrom`. They do not check a class name or a value.
- The fixed `Box` cases in `packages/core/tests/box.test.tsx`, which do check the class names and values: a number, a colour scale key, a CSS-wide keyword, a number for a property that is not a length, a responsive value, an alias, `hiddenFrom`, `null`, and a value with `;` or a brace.
- For `Box` and `Button`, a function component that spreads its props on a `<section>`, given `display`, `hiddenFrom` and `p` through them, which gets their `sx-` classes and custom properties and no `display` or `hiddenFrom` attribute. `Box` wrapping `Button` with `unstyled`, which leaves the `<button>` with none of `Button`'s library classes, and without it, which keeps them.
- That `PolymorphicProps` takes `href` when `component` is `"a"` and not when it is `"div"`, takes the props of a test component it names, refuses every display prop a test component declares `never`, and refuses a prop neither declares, such as `nonsense`, as types the checker proves once. That `Box` and `Button` with `component="a"` render an `<a>` with its `href`. That `Disclosure`'s `classes` takes `summary`, a key of its `stylex.create` block, and not `label`, also as a type the checker proves.
- That every `--sx-` declaration the generator draws for a consumer's `style` or for `styles.root` is a custom property that a style-prop class reads, aliases included.
- That every root carries exactly one class of the form `solix-<Component>-root`, its own.
- For every component, that one server render of its fixture reads each element-valued prop of its type exactly once, and that the prop given `0` renders the `0` and given each value the platform renders nothing for renders what the component renders without it. The type checker requires the fixture to name every such prop.
- For every component that another export carries, its exported name and the error it throws outside its carrier.

## What a pass does not cover

- A `Modal` that `Box` or `Button` wraps and gives `display`, `hiddenFrom` or `visibleFrom`. Their type refuses it, and nothing refuses it at run time.
- A class or attribute that changes after the first render. The check renders once on the server. `apps/playground/tests/consumer.test.ts` drives the `Emphasise` button and the `Follows` disclosure in a browser, including a class that `classes.summary` names on `Follows`. Only those two are driven, and no `styles` or `unstyled` value that changes is driven.
- Event handlers and any attribute outside the four listed. For a part bound to a behaviour slot, `packages/core/tests/headless.test.tsx` checks the order of handlers, refs and ids, and `.agents/skills/verify-headless-seam` describes it. The attributes a slot adds to a part, such as `role`, `tabindex` and `aria-selected`, are not part of this contract; it checks only that they displace no class, style or consumer attribute. `apps/playground/tests/consumer.test.ts` checks `ref` in a browser, for one instance of each component.
- A part that a component renders only for props its fixture does not give.
- How often a browser reads an element-valued prop. The count is taken in a server render; `apps/playground/tests/dev-diagnostics.test.ts` fails on the hydration key miss that a second read causes for the elements the playground passes to `Tabs.Tab`.
- Which CSS property a style prop sets, and how the browser ranks a style prop against a component default, a consumer class and a consumer `style`. `packages/core/tests/build-output.test.ts` checks the rules and their layer, and `apps/playground/tests/box.test.ts` checks the cascade in each installed engine.
- The same class name switched on in one place and off in another.
- A style-prop value that holds a comment opener `/*` or an unclosed quote. It is kept, and `packages/core/README.md` lists what it can do to the declarations after it.
- How the browser ranks a class from `classes` and a declaration from `styles` against the library's styles. `apps/playground/tests/button.test.ts` and `apps/playground/tests/disclosure.test.ts` check one case of each, and `unstyled` on `Button`, in each installed engine, and `apps/playground/tests/box.test.ts` checks a style prop on `Button`.
- What the browser does with the markup. The tests in `apps/playground/tests` cover that for the cases in the app.

## Reading a failure

- **`every component the library exports is held to the root contract` fails.** A component was added to `index.ts`, or removed. Add or remove its entry in `fixtures` in `packages/core/tests/fixtures.ts`, with its root tag, one boolean attribute its root accepts, and the props that render every part.
- **`the root carries one stable root class, its own` fails.** The root carries another component's root class, such as `solix-Box-root`, because the component renders its root through that component. Render its own element and spread `root` on it.
- **`renders, under its fixture, the root and every other key of its built styles object` fails.** Two elements carry the same part, one element carries two, the root is not the first element, or a key of the compiled `styles` object is not rendered with its stable class under the fixture's props: a `class` or `style` written next to the part spread replaced it, or the part renders only for a prop the fixture does not give.
- **`every component's source file is covered by the contract skill's table` fails.** A component's file lies outside every path of the covered-code table above. Widen a row to it, or give it a row.
- **`no prop that createParts handles, but class and style, reaches an element as an attribute` fails.** A component spread a style prop or one of `classes`, `styles`, `unstyled` and `component` on an element. Read them through `createParts` only.
- **`renders a 0 given to a prop of its type that takes an element` fails.** The message names the prop and the value. A component decides by truthiness whether to render the part; decide through `rendersSomething`.
- **`reads each prop of its type that takes an element once` fails.** The message names the prop and the count. A count of two means the component reads the prop once to decide and once to render; resolve it once with Solid's `children` and read the result. A count of zero means the component no longer renders the prop: if that is intended, declare the prop `never` in the component's type, and the fixture's `elementProps` then has no entry for it.
- **`a component that another export carries as a static member` fails.** A carried component is exported under another name than its carrier's followed by the member's, or it renders outside its carrier without the error that names the carrier.
- **`keeps every prop its fixture gives, but children, off its elements` fails.** A prop of the component's own, such as `label`, reached an element as an attribute. Pass it to `createParts` after `props`, so it stays off the root.
- **`starts with exactly the classes of its compiled styles, then its stable class` fails.** A part carries the classes of another part's styles, or of none, or a class before them. Give each part `stylex.attrs` of its own `styles` entry, in `createParts`.
- **An `expect` inside the property fails.** This is a real break. fast-check prints the smallest input under `Counterexample`: the class names with how each was written, the attributes, and the boolean flag. Report it in those terms, for example "a class written as an object key and switched off still appears on the Button". Do not loosen the assertion.
- **`The rendered markup does not start with an element`.** The component now renders something before its root, such as a fragment or a wrapper. Decide whether that is intended before changing `rootElementOf`.
- To replay one failure, add the printed `seed` and `path` to the options object passed to `fc.assert`, run again, and remove them afterwards.

## When the change is intended

- A new style prop: add a row to the table in `packages/core/src/style-prop-table.ts` and nothing else. The check draws it from there. A second name for an existing prop is a row with `aliasOf`.
- A new component: add its entry to `fixtures`; the type checker names each field it needs. A component that another carries needs no more: the fixtures read the carrier from the build. Its parts come from its build. If its root should not take consumer attributes, that breaks the contract in `AGENTS.md`, so change that rule and its check first.
- A component's root tag or boolean attribute changes: change its entry in `fixtures`.
- Upgrading Solid or the Solid plugin: change the versions in the catalog in `pnpm-workspace.yaml`, then run the check.
