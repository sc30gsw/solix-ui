# Migration to e2e

Source: Playwright driven directly from Vitest, `apps/playground/tests/**/*.test.ts`, `apps/stylex-consumer/tests/**/*.test.ts` and `apps/storybook/tests/storybook-interface.test.ts`, with their helpers in `tests/support` (guide: https://e2e.com/docs/migrate/playwright.md, engine: https://e2e.com/docs/web.md)
e2e: `e2e.config.ts`, tests `apps/playground/tests/**/*.e2e.ts`
Start dependencies: none; `vp run test:e2e` builds the packages, and each target's `app.command` starts the built playground with `node dist/server/node.js` on a free port
Run old: `vp test <file>`
Run new: `vp run test:e2e`, or `NODE_ENV=production vp run -r build` and then `E2E_TELEMETRY_DISABLED=1 npx e2e run <file>`
Harness: done, smoke `apps/playground/tests/text-input.e2e.ts` on chromium, firefox and webkit
Defect check: on

The repository allows no code comments, so a ported file does not open with a comment that names its source. The table maps each one.

## Gaps

- `web()` takes no `javaScriptEnabled`, and the guide does not list it. Every test that opens a page with scripts off stays in the old runner: the scripts-off text-input test, and the scripts-off cases of behaviour-seam, box, button, color-scheme, disclosure, layout, modal, style-nonce and tabs.
- `page.on('console')` and `page.on('pageerror')` are "Planned" in the guide. Today an init script records `console.error`, `console.warn`, uncaught errors, unhandled rejections, resources that fail to load and refusals of the page's content security policy. A message the browser itself logs for any other reason is not seen, where the old runner saw it.
- `locator.evaluate()` is "Planned". Computed styles are read with `browser.evaluate` on an `aria-label` selector that must match one element, beside the role query the test acts on.
- e2e saves a screenshot of every failed test under `.e2e/results/<test>/attempt-<n>/screenshots`, and no option turns it off ("Failure screenshots are always captured when the engine can"). The old runner's rule is that nothing saves a screenshot of a failed test. Here `.e2e` is ignored by git and no workflow uploads it.
- When a test fails, e2e's capture of the failed screen adds a stylesheet that the playground's policy refuses, so the trace's App log shows `Refused to apply a stylesheet` at the failing step. It is e2e's, not the app's. The console recorder does hear the app's own refusals: with the nonce taken off `LibraryStyle`, every test fails on its console check.
- e2e sends anonymous telemetry unless `E2E_TELEMETRY_DISABLED=1` is set. `vp run test:e2e` sets it; a bare `npx e2e` does not.
- color-scheme's storage-event test opens a second page in the same context. e2e's `browser.newTab()` covers that; it has not been tried yet.
- Generated sequences with fast-check (tabs-protocol, modal-protocol) have no e2e counterpart and have not been tried.
