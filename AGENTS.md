# AGENTS.md

Every rule in this repository is enforced by a check. Run all of them with `vp run verify`. The same command runs before each commit and in CI.

| Rule | Enforced by |
| --- | --- |
| Use Vite+ for development, builds, tests, linting and formatting. | The pnpm override that resolves `vite` to Vite+, the `vite-plus/prefer-vite-plus-imports` lint rule, and `tests/workspace-rules.test.ts`. |
| Code is formatted, lint-clean and type-correct. | `vp check --deny-warnings`. |
| Code has one style for functions, imports, exports, comparisons and type assertions. | The lint rules in `vite.config.ts`, run by `vp check --deny-warnings`. |
| No tracked file, file name or commit message names another UI library. | `scripts/check-private-terms.mjs`, in `vp run verify` and the commit-msg hook, where `SOLIX_PRIVATE_TERMS` is set. CI sets it from a repository secret. |
| A component has one shape: one function per `Component.tsx` and its exported props type, `ElementProps<"element", typeof styles, OwnProps>` or `PolymorphicProps<T, typeof styles, OwnProps>` from `packages/core/src/parts.ts`, and one `createParts` call that keeps every member of `OwnProps`, and `children` when it renders them, off the root. `OwnProps` is an inline type literal, or an intersection of them, and only `Partial<Record<DisplayPropName, never>>` may stand on its own in it. A component typed `PolymorphicProps` declares a generic overload and then one for its default element, and renders a `dynamic()` root; one typed `ElementProps` returns the element it names. Its `root` is spread on that element and `part(name)` inline on each other part, an intrinsic element. No `class` or `style` is written by hand, and no file in `packages/core/src` but `parts.ts` calls `stylex.attrs` or `stylex.props`. The barrel is sorted and exports each component with its props type, and every `--solix-*` token is used. No array or argument list outside the table in `packages/core/src/style-prop-table.ts` names two style props. | `tests/library-conventions.test.ts`. |
| A component is rendered by the app, described by a feature file, and listed in the contract skill. | `apps/playground/tests/consumer.test.ts`, `tests/library-conventions.test.ts` and `packages/core/tests/component-contract.test.tsx`. |
| Skills, agents and this table stay true to the repository, and every agent is started by an installed skill. | `tests/repository-conventions.test.ts`. |
| Every row of this table is compact, with one space on each side of each cell border and no padding, so a rule edit changes one line. The formatter leaves this file alone. | `tests/repository-conventions.test.ts`, and `fmt.ignorePatterns` in `vite.config.ts`. |
| Every list of the playground's journeys names the same journeys, each feature file has the same four sections, and no two test servers share a port. | `tests/playground-verification-conventions.test.ts`. |
| The evidence comment on a pull request holds one row per journey, linked once to that journey's section of the full report by the anchor GitHub gives its heading, with each engine's count of passed observations, and fits in GitHub's 65,536 characters for 200 journeys on every engine. Steps, screenshots, recordings and observed values stay in the full report. | `tests/evidence-summary.test.ts`. |
| `vp run verify` runs before each commit and in CI, on every browser engine, and CI gives it the private-term list. | `tests/repository-conventions.test.ts`. |
| Components follow Solid 2.0, not React or Solid 1.x. | `solid2-kit check` and `solid2-kit doctor`. |
| A dependency version is written once, in the catalog. | `catalogMode: strict` in `pnpm-workspace.yaml` and `tests/workspace-rules.test.ts`. |
| The root `package.json` sets `engines.node` to a range with a lowest major, and `@types/node` shares that major. In every `.yml` or `.yaml` workflow, each `node-version-file:` is `package.json`, no line says `node-version:`, and `node-version-file: package.json` lines are at least as many as `runs-on:` lines. No `.node-version`, `.nvmrc` or `.tool-versions` file exists outside generated and installed files, no manifest sets `devEngines.runtime`, and no manifest but the root sets `engines.node`. | `tests/workspace-rules.test.ts`. |
| The project is MIT-licensed, and every library package declares the same licence as the root. | `tests/workspace-rules.test.ts`. |
| A library's peer range accepts the version the catalog pins. | `tests/workspace-rules.test.ts`. |
| Compiler settings are written once, in `tsconfig.base.json`. | `tests/workspace-rules.test.ts`. |
| A library has no runtime dependency. As a peer, or as a library of this repository in any dependency list, the primitives package names only `solid-js`, and a component library names only `solid-js`, `@solidjs/web`, `@stylexjs/stylex` and the primitives package. A library names another library of this repository as a `workspace:^` peer, linked as a `workspace:*` devDependency. | `tests/workspace-rules.test.ts`. |
| A public module of the primitives package is a kebab-case `src/<name>.ts` that exports one function named for the file, such as `createToggle` in `create-toggle.ts` or `getHotkeyHandler` in `get-hotkey-handler.ts`, and its types. A helper that no consumer imports is `internal-<topic>.ts`, and the shared types are in `types.ts`, which exports only types. | `tests/primitive-conventions.test.ts`. |
| The primitives package's barrel re-exports each public module with its types, then `types.ts`, in file-name order, and no internal module. | `tests/primitive-conventions.test.ts`. |
| A primitive names no `createRenderEffect` and no `createTrackedEffect`, as an identifier or as a string looked up on an object. | `tests/primitive-conventions.test.ts`. |
| A primitive keeps no state at module level: no `let` or `var`, no static class field, no module-level initialiser that holds `new`, a regular expression literal or a call other than `Symbol(...)` and `Object.freeze(...)`, and no array or object literal that is not `as const`. | `tests/primitive-conventions.test.ts`. |
| A primitive reads once, untracked, when it is created, only an argument named `initial*`, `default*` or `final*`, and an argument is typed `ReadOnce` exactly when it is so named. | `tests/primitive-conventions.test.ts`. |
| In a primitive's body, outside nested closures, no parameter is destructured, and no declaration, `Object.assign` source or spread takes its value from a parameter except through a call, with each binding resolved by the type checker. | `tests/primitive-conventions.test.ts`. |
| A primitive writes no style and no class: it assigns no `style`, `className` or `classList`, calls none of their writers, passes `class` or `style` to no attribute writer, even through a constant, and creates no `<style>` element or adopted style sheet. It may read them. | `tests/primitive-conventions.test.ts`. |
| Each rule of `tests/primitive-conventions.test.ts` passes a fixture that holds only what it allows, and flags every line of a fixture that breaks it. | The fixture tests in `tests/primitive-conventions.test.ts`. |
| Each request decides on the value staged by the requests before it in the same tick; a request that changes nothing writes nothing and calls nothing. Every primitive that keeps its state in `internal-value.ts` has a browser test that checks this for generated sequences against a model built on `packages/primitives/tests/support/model.ts`, with `fc.modelRun`. | `tests/primitive-conventions.test.ts` and those browser tests. |
| Every primitive has a server-render case in a table that is a mapped type over the barrel's `create*` exports, so a missing case fails the type check. Read from the build, each one renders on the server with every name in `packages/primitives/tests/support/browser-resources.ts` trapped, gives its server value, and returns nothing or only functions. | `packages/primitives/tests/server-render.test.ts`, type-checked by `vp check --deny-warnings`. |
| Node's own loader imports the built primitives package. | `packages/primitives/tests/build-output.test.ts`. |
| Every primitive has a browser test, `tests/<file>.browser.test.ts` or `.tsx`, that runs in each engine and fails on any Solid development diagnostic and on any listener, timer or observer left after its owner is disposed, and every plain helper has a Node test, `tests/<file>.test.ts`. | `tests/primitive-conventions.test.ts` and `packages/primitives/tests/support/browser-harness.ts`, set up for the browser project in `vite.config.ts`. |
| A colour token is written in OKLCH and lies inside sRGB. In every `stylex.create` block of a component, under each condition, `color` reaches 4.5:1 contrast and each border or outline colour 3:1 against the block's `backgroundColor`, or against `--solix-color-body` when the block sets none. Each colour in such a pair is a token. | `packages/core/tests/token-contrast.test.ts`. |
| The library's CSS sits in one cascade layer, its classes carry the library prefix, and nothing is `!important`. | `packages/core/tests/build-output.test.ts` and `packages/core/tests/stylesheet-properties.test.ts`. |
| Every exported component puts a consumer's class and attributes on its root, next to its own classes, and the root carries one stable root class, its own, unless `component` names another component. Every key of its compiled `stylex.create` block is a rendered part and every part is a key, and each part's element starts with exactly the classes that key compiles to. It puts the class and the declarations that `classes` and `styles` name for a part on exactly that part, leaves out a declaration whose value is `undefined` or `null`, and with `unstyled` keeps every stable part class and drops every class of its compiled styles. | `packages/core/tests/component-contract.test.tsx`. |
| Every exported component passes a consumer's `ref` the element that carries its root class. | `apps/playground/tests/consumer.test.ts`. |
| Every component takes every style prop on its root, except one its type declares `never`: `Modal` takes no `display`, `hiddenFrom` or `visibleFrom`. A polymorphic component refuses, in its type only, every style prop that the component its `component` names declares `never`. It resolves every style prop it is given, display ones included, whatever `component` names, and when `component` names a function it passes `classes`, `styles` and `unstyled` to it as well as applying them to its own root. A style prop writes into `style` only the `--sx-` custom property its own class reads, and drops `null` and any value that holds `;`, `{` or `}`. Each `--sx-` custom property is registered not to inherit. A longhand style prop's rules come after its shorthand's at every breakpoint. Precedence is component default < style prop < consumer class < consumer `style`. The style-prop table that the build loads imports nothing at run time. | `packages/core/tests/component-contract.test.tsx`, `packages/core/tests/build-output.test.ts`, `packages/core/tests/stylesheet-properties.test.ts` and `apps/playground/tests/box.test.ts`. |
| A check that covers every component reads the components from the build, not from a list written by hand. A per-component table is a mapped type over the library's exports, and no array in a test file lists components by name. | `packages/core/tests/built-library.ts`, used by `packages/core/tests/build-output.test.ts`, `packages/core/tests/component-contract.test.tsx` and `apps/playground/tests/consumer.test.ts`, the mapped type in `packages/core/tests/fixtures.ts`, and `tests/library-conventions.test.ts`, which fails on an array in a test file whose strings all name components, and on an object literal there whose keys all name components unless its type is a mapped type over the keys of the library's exports. |
| A consumer's own StyleX classes and token overrides beat the library. | `apps/stylex-consumer/tests/stylex-consumer.test.ts`. |
| A consumer needs no StyleX build setup, and a consumer's plain class beats the library's styles. | `apps/playground/tests/consumer.test.ts` and `apps/playground/tests/button.test.ts`. |
| A component or a primitive behaves the same in Chromium, Firefox and WebKit. | The browser tests run once per engine in `scripts/browser-engines.mjs`, which the browser project in `vite.config.ts` reads when it starts, and CI fails unless all three are installed. |
| Our code raises no Solid development diagnostic, and a known upstream one is listed with an expiry date. | `apps/playground/tests/dev-diagnostics.test.ts`, and for the primitives `packages/primitives/tests/support/browser-harness.ts`. |
| The project keeps working on the newest Solid 2 release. | The weekly `Newest Solid 2` workflow, which runs `vp run verify` against it. |
