# AGENTS.md

Every rule in this repository is enforced by a check. Run all of them with `vp run verify`. The same command runs before each commit and in CI.

| Rule | Enforced by |
| --- | --- |
| Use Vite+ for development, builds, tests, linting and formatting. | The pnpm override that resolves `vite` to Vite+, the `vite-plus/prefer-vite-plus-imports` lint rule, and `tests/workspace-rules.test.ts`. |
| Code is formatted, lint-clean and type-correct. | `vp check --deny-warnings`. |
| Code has one style for functions, imports, exports, comparisons and type assertions. | The lint rules in `vite.config.ts`, run by `vp check --deny-warnings`. |
| No tracked file, file name or commit message names another UI library. | `scripts/check-private-terms.mjs`, in `vp run verify` and the commit-msg hook, where `SOLIX_PRIVATE_TERMS` is set. CI sets it from a repository secret. |
| A component has one shape: one function per `Component.tsx` and its exported props type, `ElementProps<"element", typeof styles, OwnProps>` or `PolymorphicProps<T, typeof styles, OwnProps>` from `packages/core/src/parts.ts`, and one `createParts` call that keeps every member of `OwnProps`, and `children` when it renders them, off the root. `OwnProps` is an inline type literal, or an intersection of them, and only `Partial<Record<DisplayPropName, never>>` may stand on its own in it. A component typed `PolymorphicProps` declares a generic overload and then one for its default element, and renders a `dynamic()` root; one typed `ElementProps` returns the element it names. Its `root` is spread on that element and `part(name)` inline on each other part, an intrinsic element. No `class` or `style` is written by hand, and no file in `packages/core/src` but `parts.ts` calls `stylex.attrs` or `stylex.props`. The barrel is sorted and exports each component with its props type, and every `--solix-*` token is used. No array or argument list outside the table in `packages/core/src/style-prop-table.ts` names two style props. | `tests/library-conventions.test.ts`. |
| A component is rendered by the app, described by a feature file, and listed in the contract skill. | `apps/playground/tests/consumer.test.ts`, `tests/library-conventions.test.ts` and `packages/core/tests/component-contract.test.tsx`. |
| Skills, agents and this table stay true to the repository, and every agent is started by an installed skill. | `tests/repository-conventions.test.ts`. |
| Every row of this table is compact, with one space on each side of each cell border and no padding, so a rule edit changes one line. The formatter leaves this file alone. | `tests/repository-conventions.test.ts`, and `fmt.ignorePatterns` in `vite.config.ts`. |
| Every list of the playground's journeys names the same journeys, each feature file has the same four sections, and no two test servers share a port. | `tests/playground-verification-conventions.test.ts`. |
| `vp run verify` runs before each commit and in CI, on every browser engine, and CI gives it the private-term list. | `tests/repository-conventions.test.ts`. |
| Components follow Solid 2.0, not React or Solid 1.x. | `solid2-kit check` and `solid2-kit doctor`. |
| A dependency version is written once, in the catalog. | `catalogMode: strict` in `pnpm-workspace.yaml` and `tests/workspace-rules.test.ts`. |
| The project is MIT-licensed, and every library package declares the same licence as the root. | `tests/workspace-rules.test.ts`. |
| A library's peer range accepts the version the catalog pins. | `tests/workspace-rules.test.ts`. |
| Compiler settings are written once, in `tsconfig.base.json`. | `tests/workspace-rules.test.ts`. |
| The library is built on web standards and has no runtime dependency beyond its Solid and StyleX peers. | `tests/workspace-rules.test.ts`. |
| A colour token is written in OKLCH and lies inside sRGB. In every `stylex.create` block of a component, under each condition, `color` reaches 4.5:1 contrast and each border or outline colour 3:1 against the block's `backgroundColor`, or against `--solix-color-body` when the block sets none. Each colour in such a pair is a token. | `packages/core/tests/token-contrast.test.ts`. |
| The library's CSS sits in one cascade layer, its classes carry the library prefix, and nothing is `!important`. | `packages/core/tests/build-output.test.ts` and `packages/core/tests/stylesheet-properties.test.ts`. |
| Every exported component puts a consumer's class and attributes on its root, next to its own classes, and the root carries one stable root class, its own. Every key of its compiled `stylex.create` block is a rendered part and every part is a key, and each part's element starts with exactly the classes that key compiles to. It puts the class and the declarations that `classes` and `styles` name for a part on exactly that part, leaves out a declaration whose value is `undefined` or `null`, and with `unstyled` keeps every stable part class and drops every class of its compiled styles. | `packages/core/tests/component-contract.test.tsx`. |
| Every exported component passes a consumer's `ref` the element that carries its root class. | `apps/playground/tests/consumer.test.ts`. |
| Every component takes every style prop on its root, except one its type declares `never`: `Modal` takes no `display`, `hiddenFrom` or `visibleFrom`, which would show a closed dialog. A polymorphic component refuses, in its type only, every style prop that the component its `component` names declares `never`. It resolves every style prop it is given, display ones included, whatever `component` names, and when `component` names a function it passes `classes`, `styles` and `unstyled` to it as well as applying them to its own root. A style prop writes into `style` only the `--sx-` custom property its own class reads, and drops `null` and any value that holds `;`, `{` or `}`. Each `--sx-` custom property is registered not to inherit. A longhand style prop's rules come after its shorthand's at every breakpoint. Precedence is component default < style prop < consumer class < consumer `style`. The style-prop table that the build loads imports nothing at run time. | `packages/core/tests/component-contract.test.tsx`, `packages/core/tests/build-output.test.ts`, `packages/core/tests/stylesheet-properties.test.ts` and `apps/playground/tests/box.test.ts`. |
| A check that covers every component reads the components from the build, not from a list written by hand. A per-component table is a mapped type over the library's exports, and no array in a test file lists components by name. | `packages/core/tests/built-library.ts`, used by `packages/core/tests/build-output.test.ts`, `packages/core/tests/component-contract.test.tsx` and `apps/playground/tests/consumer.test.ts`, the mapped type in `packages/core/tests/fixtures.ts`, and `tests/library-conventions.test.ts`, which fails on an array in a test file whose strings all name components. |
| A consumer's own StyleX classes and token overrides beat the library. | `apps/stylex-consumer/tests/stylex-consumer.test.ts`. |
| A consumer needs no StyleX build setup, and a consumer's plain class beats the library's styles. | `apps/playground/tests/consumer.test.ts` and `apps/playground/tests/button.test.ts`. |
| A component behaves the same in Chromium, Firefox and WebKit. | The browser tests run once per engine in `scripts/browser-engines.mjs`, and CI fails unless all three are installed. |
| Our code raises no Solid development diagnostic, and a known upstream one is listed with an expiry date. | `apps/playground/tests/dev-diagnostics.test.ts`. |
| The project keeps working on the newest Solid 2 release. | The weekly `Newest Solid 2` workflow, which runs `vp run verify` against it. |
